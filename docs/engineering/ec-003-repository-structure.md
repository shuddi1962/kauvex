## Purpose

This is the canonical map of the Kauvex Commerce Cloud repository: where every kind of code lives, what each area is for, and who owns it. It exists so the AI agent can orient in seconds, place new files in the right directory, and never move or restructure existing ones. The golden rule: new features add files; they do not relocate existing ones.

## Rules

1. New features add files; they NEVER move existing files, directories, or routes. If a feature genuinely requires restructuring, it must be called out to the user first.
2. New pages go under `src/app/<area>/<page>/page.tsx`. New route handlers go under `src/app/api/v1/<group>/<resource>/route.ts`. Reuse an existing group where one fits (e.g. new KAI endpoints go under `src/app/api/v1/kai/` or `src/app/api/v1/kai-business/`).
3. New business logic goes in `src/lib/<module>/` with an `index.ts` entry point; single-file logic may sit at `src/lib/` root (see `buybox.ts`, `search-engine.ts`).
4. New shared UI goes in `src/components/ui/`; feature-specific UI goes in `src/components/<feature>/`.
5. Database model changes: append to `prisma/schema.prisma`; the corresponding SQL goes in a new `supabase/migrations/NNN_kcc_phaseXX_name.sql` file. Never edit an applied migration.
6. Never hand-edit `src/generated/prisma/` — regenerate with `npx prisma generate`.
7. Never put runtime code in `scripts/`; those are maintenance tools run manually or by the founder.
8. `docs/canvas/` is user-owned; `docs/engineering/` is agent-owned (per EC-001 ownership rules).
9. After adding or renaming major directories, update `AGENTS.md` and regenerate `.opencode/workspace-index.md` via `node scripts/workspace-index.mjs`.
