# EC-010 — Documentation Standards

> **Status:** Active
> **Phase:** A — Engineering Foundation
> **Canonical code:** `docs/`, `AGENTS.md`, `.opencode/`
> **Overrides:** nothing

## Purpose

Defines where documentation lives, who owns it, and how it stays honest. The rule that keeps this repo usable at scale: **documentation must reflect the repo as it is today, not as envisioned**. Any doc that describes a path, model, or command that doesn't exist is a defect.

## Current Truth (in this repo today)

- **`docs/canvas/`** — user-owned vision documents (21 numbered docs 01–21 + `system-architecture.md`). NEVER edited by the agent. Define "what Kauvex becomes".
- **`docs/engineering/`** — agent-owned EC series (EC-001..EC-050). Define "how the code is built". EC-001..EC-005 require user approval to change; others may evolve with phases but "Current Truth" sections must stay accurate.
- **`docs/PROGRESS.md`** — handover file: complete vs pending, resume points, key commands. Updated when a milestone lands or a pending item is created.
- **`AGENTS.md`** — shared project context: stack, directories, modules, brand, phases, knowledge bases per phase. Updated when major modules or phases are added.
- **`.opencode/workspace-index.md`** — fast-orientation index generated by `node scripts/workspace-index.mjs`; regenerated after major structural changes.
- **Migrations** — `supabase/migrations/000NN_kcc_phaseXX_name.sql`; append-only, never edited after apply (EC-011).
- Code comments: only where meaningful (per EC-004, no comments unless asked); doc-strings kept short.

## Rules

1. Every fact written into docs MUST be verified against the repo (paths, model names, commands). Never document something that doesn't exist.
2. When a new phase or major module ships, update `AGENTS.md` (add directory + knowledge-base section) and `docs/PROGRESS.md` (move item to complete; add pending items).
3. Migration naming: `supabase/migrations/000NN_kcc_phaseXX_name.sql` — NN is the next number after the highest existing; `phaseXX` matches the roadmap phase.
4. Vision documents are read-only for the agent (EC-001 Rule 6).
5. EC docs use the shared template (header block → Purpose → Current Truth → Rules → Evolution Targets → Checklist) so they can be scanned quickly.
6. New EC documents may only be created with a purpose that no existing EC doc covers, and must be registered in `docs/engineering/README.md` index.
7. The agent documents deviations from these standards in `docs/PROGRESS.md` rather than silently skipping them.

## Checklist (Definition of Done for this area)

- [ ] New module/phase reflected in AGENTS.md
- [ ] PROGRESS.md updated (done/pending)
- [ ] Migration named per convention
- [ ] No fictional paths/models documented anywhere
- [ ] Workspace index regenerated if structure changed
