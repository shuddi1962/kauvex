# VISION

Kauvex is not an e-commerce platform.

Kauvex is not a business software.

Kauvex is not a marketplace.

Kauvex is not an ERP.

Kauvex is not an AI assistant.

# GUIDING PRINCIPLES FOR EVERY FEATURE

Every new feature should answer:

* Does it make businesses more productive?
* Does it simplify complex work?
* Does it integrate with the ecosystem?
* Does AI make it better?
* Can it scale globally?
* Can it serve multiple industries?
* Does it improve collaboration?
* Is it modular?
* Is it secure?
* Is it future-ready?

If the answer is "no" to most of these questions, reconsider the feature before implementation.

---

# AI CODING DIRECTIVE

Every AI coding agent working on Kauvex must follow these rules:

1. Never replace stable functionality unless explicitly instructed.
2. Build new capabilities as modular, reusable components.
3. Prioritize performance, accessibility, responsiveness, and maintainability.
4. Use clean architecture with clear separation of concerns.
5. Ensure every module integrates with KAI, Business OS, Marketplace, and Analytics where appropriate.
6. Prefer browser-native technologies over platform-specific desktop dependencies.
7. Design every feature with enterprise scalability and multi-tenant support in mind.
8. Keep APIs versioned and extensible.
9. Make every workflow configurable through feature flags and admin settings.
10. Build for the next decade, not just the next release.
